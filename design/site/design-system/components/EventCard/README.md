# EventCard

Карточка мероприятия для каталога и главной: предметы, дата-плашка, название, уровень и тип, цена и статус регистрации — всё, что нужно учителю и директору, чтобы решить «идём или нет».

## Варианты

- **Сетка** (`q-event`): на 390 карточки столбиком, на 1440 — три в ряд (`q-cols--3`), одинаковой высоты (подвал прижат `margin-top: auto`).
- **Строка** (`q-event--row`, только 1440): дата 72 px слева, текст по центру, цена и статус справа — для архива и списков по 10–20 позиций.
- **Прошедшее** (`q-event--past`): фон `surface-alt`, дата-плашка белая; статус `q-status--past`; вместо цены — «Итоги» (ссылка внутри карточки ведёт к результатам).

## Состав

`q-event__top` (теги предметов `q-tag--math|physics|informatics`) → `q-event__date` (`q-event__day`: число и месяц прописными; «—» и год, если дата не утверждена) + `q-event__when` / `q-event__where` (город · очно / онлайн, иконка `map-pin` или `monitor`) → `q-event__title` 18/24 (20/26 на 1440, 600) → `q-event__meta` (уровень · тип) → `q-event__foot`: `q-event__price` («50 000 ₸» + `small` «от школы — от 5 участников») и `q-status`.

## Правила

- Вся карточка — одна ссылка `<a>` на страницу мероприятия; внутри нет вложенных кнопок.
- Цена: `price` в тенге, неразрывные пробелы; `null` → «Стоимость уточняется»; `0` → «Бесплатно».
- Дата-плашка: `startDate`–`endDate` в одном месяце — «5–6 · дек»; в разных — «30 ноя – 2 дек» строкой, в плашке первая дата.
- Не больше трёх тегов; у мультипредметного конкурса — все три.
- Рамка `line`, радиус `radius-md`, отступ 20 / 24 px; тени нет, наведение — рамка `line-strong`.

## Что передаёт потребитель

`events`: `title`, `slug`, `subjects[]`, `type`, `level`, `format`, `city`, `startDate`, `endDate`, `registrationDeadline`, `price`, `groupMinSize`; статус — вычисленное поле.
